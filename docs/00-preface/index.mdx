# 第 0 章：前言

> 在你开始"做科研"之前，先学会"用电脑做科研"。

## 本章目标

读完本章后，你应该能：

- 理解为什么理论/计算物理学生需要系统性的计算环境训练
- 了解本教程的适用对象和覆盖范围
- 根据自己的操作系统选择合适的阅读路径
- 制定适合自己的学习计划

## 0.1 这份教程是写给谁的

这份教程写给以下读者：

- **物理系本科高年级学生**：即将进入课题组，需要用电脑做数值计算、数据分析或理论推导辅助
- **研究生新生**：刚进入计算物理、凝聚态、高能、天体等方向，发现"会一点 Python"远远不够
- **自学者**：对理论/计算物理感兴趣，想建立一套完整的科研计算工作流
- **需要"补课"的高年级研究生**：一直在"凑合用"，想系统整理自己的计算环境

:::info 你不需要是"电脑高手"
本教程假设你能打开电脑、上网、装软件——仅此而已。所有概念都会从头讲起。
:::

### 一个典型的困境

你可能遇到过这样的情况：

1. 导师说"用 Fortran 跑个蒙特卡洛模拟"，你连 Fortran 编译器都不知道怎么装
2. 师兄给你一个 Python 脚本，你运行时报错 `ModuleNotFoundError`，不知道怎么解决
3. 你想把代码传到超算上跑，但不会用 SSH
4. 论文里的图要修改，但你忘了当时用的是哪个版本的代码
5. 换了新电脑，花了两天重新配环境

这些问题的根源不是你"不够聪明"，而是**没有人系统地教过你如何搭建和管理科研计算环境**。

## 0.2 学完之后你能做什么

完成本教程后，你将具备以下能力：

| 能力 | 具体表现 |
|------|----------|
| 命令行操作 | 熟练使用终端完成日常文件管理、程序运行 |
| 环境管理 | 独立安装和配置 Python、C/C++、Fortran 等语言环境 |
| 版本控制 | 使用 Git 管理代码，用 GitHub 协作 |
| 远程计算 | 通过 SSH 连接服务器和超算，提交任务 |
| 文档写作 | 用 Markdown 和 LaTeX 写笔记和论文 |

| 数据处理 | 使用 NumPy、SciPy、Matplotlib 等科学计算工具链 |
| 并行计算 | 理解 OpenMP 和 MPI 的基本用法 |

## 0.3 三个平台说明：macOS / Ubuntu / Windows

本教程同时覆盖三个主流操作系统：

### macOS

- 物理学界使用比例很高
- 自带类 Unix 环境，终端和 Shell 开箱即用
- 通过 Homebrew 安装各种工具非常方便

### Ubuntu (Linux)

- 超算和服务器的标准系统
- 科学计算软件支持最好
- 作为桌面系统也完全可行，尤其适合需要大量本地计算的场景

### Windows

- 最常用的桌面系统
- 过去在科研计算方面有诸多不便，但现在通过 **WSL (Windows Subsystem for Linux)** 已经大幅改善
- 本教程会指导你安装和配置 WSL，让你在 Windows 上获得接近原生 Linux 的体验

:::tip 平台选择建议
如果你刚开始，不需要纠结平台选择。本教程会在每个关键步骤标注三个平台的差异。用你手边的电脑就好。
:::

## 0.4 如何使用这份教程

### 阅读方式

- **顺序阅读**：如果你是纯新手，建议从第 0 章读到第 8 章，建立基本功
- **按需跳读**：如果你已有一定基础，可以直接跳到需要的章节

每章都有**验证测试**和**练习**。请务必亲手操作，不要只看不做。

```
学编程和学游泳一样——光看教程是学不会的。
```

## 0.6 常见学习误区

### 误区一："我先把 Python 学精通，再学别的"

Python 语言本身只是工具链的一部分。如果你不会管理虚拟环境、不会用命令行、不会用 Git，即使 Python 语法很熟也无法高效做科研。**工具链的广度比单一语言的深度更重要。**

### 误区二："我直接用 Jupyter Notebook 就行"

Jupyter Notebook 是很好的交互式工具，但它不能替代：
- 版本控制（`.ipynb` 文件的 diff 非常难读）
- 可复现的批量计算
- 在服务器上提交长时间运行的任务
- 模块化的代码组织

### 误区三："配环境太麻烦，能跑就行"

"能跑就行"的环境往往会在以下时刻崩溃：
- 换了新电脑
- 需要在服务器上复现结果
- 半年后回来修改代码
- 和同事协作

花时间建立规范的工作流，长远来看会节省大量时间。

### 误区四："Linux 太难了，我用 Windows 就好"

现代 Windows 通过 WSL 已经可以获得很好的 Linux 体验。你不需要"放弃 Windows"，但你确实需要学会在类 Unix 环境中工作，因为几乎所有服务器和超算都运行 Linux。

### 误区五："AI 可以帮我搞定一切"

AI 编程助手（如 GitHub Copilot、ChatGPT）确实非常有用，但如果你不理解基本概念，你就无法：
- 判断 AI 生成的代码是否正确
- 调试 AI 无法解决的环境问题
- 理解 AI 给出的建议

**基础知识让你成为 AI 的有效使用者，而不是被 AI 牵着走。**

## 从"会一点 Python"到"能独立做科研"

很多物理学生的计算能力停留在"会一点 Python"的阶段：

- 能在 Jupyter Notebook 里写几行代码画个图
- 知道 `numpy` 和 `matplotlib`
- 复制粘贴师兄的代码，改改参数能跑

但独立科研需要的是：

- 在服务器上编译运行别人的 C++ / Fortran 程序
- 管理多个项目的 Python 环境，互不干扰
- 用 Git 追踪代码变化，回退到任意历史版本
- 写 Makefile 自动化编译流程
- 用 Shell 脚本批量提交计算任务
- 规范地组织数据、代码和论文

**这中间的差距，就是本教程要帮你填补的。**
