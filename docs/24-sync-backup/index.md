# 第 24 章：同步、备份与数据管理

> 数据丢了，实验就白做了。

## 本章目标

读完本章后，你应该能：

- 认识到数据丢失的真实风险并建立防范意识
- 区分"同步"和"备份"的概念
- 合理选择和使用云同步工具
- 为代码、数据、笔记、论文建立分门别类的管理策略
- 理解并实践 3-2-1 备份原则
- 避免常见的同步与备份错误

## 动机

以下场景在科研中屡见不鲜：

- 笔记本电脑进水/丢失，几个月的代码和数据全没了
- 硬盘突然损坏，毕业论文只剩一周前的版本
- 不小心删除了关键数据文件，回收站也清空了
- 把虚拟环境和 `node_modules` 同步到云盘，占满了空间
- 两台电脑上的文件版本冲突，不知道哪个是最新的

**这些问题都可以通过合理的同步和备份策略避免。**

## 24.1 为什么"数据丢失"是真实风险

### 数据丢失的常见原因

| 原因 | 概率 | 影响 |
|------|------|------|
| 硬盘故障 | 中 | 所有本地数据丢失 |
| 误删除 | 高 | 特定文件丢失 |
| 电脑丢失/损坏 | 低 | 所有本地数据丢失 |
| 勒索软件/病毒 | 低-中 | 数据被加密或破坏 |
| 同步冲突覆盖 | 中 | 文件被错误版本覆盖 |
| 系统崩溃 | 中 | 未保存的工作丢失 |

:::caution 真实案例
- 某研究生毕业前硬盘损坏，三年的计算数据全部丢失，延毕半年
- 某博士后误删了包含所有模拟结果的目录，没有备份
- 某课题组服务器被勒索软件攻击，三个学生的数据受影响
:::

## 24.2 Dropbox / OneDrive / 坚果云 的角色

### 主流云同步工具对比

| 特性 | Dropbox | OneDrive | 坚果云 | Google Drive |
|------|---------|----------|--------|-------------|
| 免费空间 | 2 GB | 5 GB | 1 GB/月上传 | 15 GB |
| 付费方案 | 较贵 | Microsoft 365 含 1 TB | 较便宜 | Google One |
| 中国大陆速度 | 慢/需VPN | 中等 | 快 | 慢/需VPN |
| 选择性同步 | 支持 | 支持 | 支持 | 支持 |
| 版本历史 | 30天/180天 | 30天 | 支持 | 30天 |
| WebDAV | 不支持 | 不支持 | 支持 | 不支持 |
| Linux 客户端 | 官方支持 | 非官方 | 官方支持 | 非官方 |

### 选择建议

- **中国大陆用户首选**：坚果云（速度快、WebDAV 支持好、与 Zotero 配合）
- **有 Microsoft 365**：OneDrive（1 TB 大空间）
- **国际协作**：Dropbox 或 Google Drive
- **多平台同步**：坚果云或 Dropbox（Linux 支持好）

:::info 同步 ≠ 备份
云同步的主要目的是**多设备访问**。如果你在一台设备上误删文件，同步工具会把删除操作同步到所有设备。所以同步**不能替代备份**。
:::

## 24.3 什么适合同步，什么不适合同步

### 适合同步的内容

| 类型 | 原因 | 工具 |
|------|------|------|
| 论文草稿（LaTeX/Word） | 需要多设备编辑 | 坚果云 / OneDrive |
| 研究笔记 | 随时查阅和编辑 | 坚果云 / Obsidian Sync |
| 配置文件 (dotfiles) | 多台机器保持一致 | Git + GitHub |
| 小型脚本 | 方便在不同机器使用 | Git |
| 文献 PDF（通过 Zotero） | 多设备阅读 | Zotero + WebDAV |
| 幻灯片 | 会议/组会使用 | 坚果云 / OneDrive |

### 不适合同步的内容

| 类型 | 原因 | 正确做法 |
|------|------|---------|
| 虚拟环境 (`.venv/`, `venv/`) | 体积大、平台不兼容 | `requirements.txt` + 重建 |
| `node_modules/` | 体积极大 | `package.json` + `npm install` |
| 编译产物 (`build/`, `*.o`) | 可重新生成 | Makefile + 重新编译 |
| 大型数据集 (> 1 GB) | 占空间、同步慢 | 专用存储或 Git LFS |
| `.git/` 目录 | 会与 Git 冲突 | 用 Git 管理代码，不要同步 .git |
| 临时文件、缓存 | 无价值 | 忽略 |

:::caution 严重警告
**永远不要用云同步工具同步 Git 仓库的 `.git/` 目录。** 这会导致仓库损坏。代码用 Git 管理，不要放在同步文件夹中——或者在同步工具中排除 `.git/` 目录。
:::

## 24.4 代码、数据、笔记、论文的管理建议

### 代码管理

```
管理方式：Git + GitHub/GitLab
备份方式：推送到远程仓库
注意事项：
  - 不要提交敏感信息（密钥、密码）
  - 不要提交大型二进制文件
  - 使用 .gitignore 排除不需要的文件
```

### 数据管理

```
小型数据（< 100 MB）：随代码放在 Git 仓库中
中型数据（100 MB - 10 GB）：Git LFS 或共享存储
大型数据（> 10 GB）：专用存储（服务器、NAS）
注意事项：
  - 记录数据的来源和生成方式
  - 原始数据只读，不要修改
  - 处理后的数据可以重新生成
```

### 笔记管理

```
管理方式：Obsidian / Markdown 文件
同步方式：坚果云 / Obsidian Sync / Git
备份方式：云同步 + 本地备份
注意事项：
  - 用 Markdown 格式，避免私有格式
  - 定期整理和归档
```

### 论文管理

```
管理方式：LaTeX + Git
同步方式：Overleaf（在线） 或 Git + 云同步
备份方式：Git + Overleaf + 本地备份
注意事项：
  - 每次重要修改后 commit
  - 保存所有版本的 PDF
  - 参考文献用 Zotero + Better BibTeX 管理
```

## 24.5 本地备份、云端备份、版本控制

### 三种保护方式的对比

| 方式 | 保护什么 | 不保护什么 | 工具 |
|------|---------|-----------|------|
| 版本控制 (Git) | 代码的每次变更 | 大型数据文件 | Git, GitHub |
| 云端同步 | 多设备访问 | 防误删（同步删除） | 坚果云, OneDrive |
| 本地备份 | 完整数据副本 | 灾难性事故（火灾等） | Time Machine, rsync |
| 云端备份 | 异地数据副本 | 无 | Backblaze, 阿里云 OSS |

### 本地备份工具

**macOS: Time Machine**

```bash
# 连接外置硬盘后，系统会提示是否用于 Time Machine
# 或手动配置：
# 系统设置 → 通用 → Time Machine → 添加备份磁盘
```

**Linux: rsync**

```bash
# 备份到外置硬盘
rsync -avh --progress ~/research/ /mnt/backup/research/

# 增量备份（只复制变化的文件）
rsync -avh --delete ~/research/ /mnt/backup/research/

# 定期自动备份（添加到 crontab）
crontab -e
# 每天凌晨 2 点备份
# 0 2 * * * rsync -avh --delete ~/research/ /mnt/backup/research/
```

**Windows: 文件历史记录**

```
设置 → 更新和安全 → 备份 → 使用文件历史记录进行备份
```

## 24.6 一个推荐目录结构

### 科研工作的根目录

```
~/research/                    # 或 D:\research\（Windows）
│
├── projects/                  # 科研项目（Git 管理）
│   ├── ising-model/           # 项目 1
│   ├── topological-insulator/ # 项目 2
│   └── md-simulation/         # 项目 3
│
├── papers/                    # 论文写作（Git 管理）
│   ├── paper-2025-ising/
│   └── thesis/
│
├── notes/                     # 研究笔记（云同步）
│   ├── courses/
│   ├── seminars/
│   └── reading-notes/
│
├── literature/                # 文献（Zotero 管理）
│   └── zotero-storage/        # Zotero 附件目录
│
├── presentations/             # 报告和幻灯片（云同步）
│   ├── group-meeting/
│   └── conferences/
│
├── data/                      # 共享数据（大型数据专用存储）
│   ├── raw/                   # 原始数据（只读）
│   └── processed/             # 处理后数据
│
└── tools/                     # 个人工具和脚本
    ├── dotfiles/              # 配置文件（Git 管理）
    └── scripts/               # 常用脚本
```

### 目录管理原则

| 原则 | 说明 |
|------|------|
| 按类型分目录 | 代码、论文、笔记、数据分开放 |
| 每个项目独立 | 一个项目一个目录，内含完整信息 |
| 合适的工具管理 | 代码用 Git，笔记用云同步，文献用 Zotero |
| 命名规范统一 | 用小写字母和连字符，不用空格 |
| 定期清理归档 | 完成的项目移到 `archive/` |

:::tip 不要把所有东西都放桌面
`Desktop/` 和 `Downloads/` 只是临时中转站。下载的文件应该在 24 小时内归类到正确的目录。
:::

## 24.7 常见错误：把虚拟环境和大数据集都同步了

### 错误 1: 同步虚拟环境

```bash
# 错误：把 .venv 放在同步目录中
~/Dropbox/project/.venv/     # ❌ 数百 MB，跨平台不兼容

# 正确：只同步 requirements.txt
~/Dropbox/project/requirements.txt    # ✅ 几 KB

# 在新机器上重建环境
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 错误 2: 同步 node_modules

```bash
# node_modules 可能有上万个小文件，几百 MB
~/OneDrive/web-project/node_modules/   # ❌

# 正确做法
~/OneDrive/web-project/package.json    # ✅
npm install   # 重新安装
```

### 错误 3: 同步 .git 目录

```bash
# .git 目录包含大量小文件，与同步工具冲突
~/Dropbox/my-repo/.git/    # ❌ 可能损坏仓库

# 正确做法：代码用 Git 管理，不放在同步目录中
~/projects/my-repo/         # Git 管理
~/Dropbox/notes/           # 云同步管理
```

### 错误 4: 同步大型数据文件

```bash
# 几 GB 的 HDF5 文件不应该放在同步目录
~/OneDrive/project/data/huge_dataset.hdf5   # ❌

# 正确做法
# 大数据放在本地或服务器专用存储
# 只同步数据的元信息和处理脚本
~/OneDrive/project/data/README.md           # ✅ 数据说明
~/OneDrive/project/scripts/process_data.py  # ✅ 处理脚本
```

### 云同步排除规则

大多数同步工具支持排除特定文件夹：

```bash
# 坚果云：在客户端设置中添加排除规则
# 排除以下模式：
.venv/
venv/
node_modules/
__pycache__/
build/
.git/
*.pyc
*.o
```

## 24.8 3-2-1 备份思想

### 什么是 3-2-1 备份

```
3 — 至少保留 3 份数据副本
2 — 存储在 2 种不同的介质上
1 — 其中 1 份存放在异地（offsite）
```

### 实际应用示例

```
副本 1: 本地电脑（工作副本）
    │   介质：SSD/HDD
    │
副本 2: 外置硬盘或 NAS
    │   介质：外置 HDD
    │   方式：每周 rsync / Time Machine
    │
副本 3: 云端
        介质：云存储
        方式：Git push / 云同步 / 云备份
```

### 对于科研数据的 3-2-1 实践

| 数据类型 | 副本 1 | 副本 2 | 副本 3 |
|---------|--------|--------|--------|
| 代码 | 本地电脑 | GitHub | 服务器上的克隆 |
| 论文 | 本地电脑 | Overleaf/Git | 云同步 |
| 笔记 | 本地电脑 | 云同步 | Git 仓库 |
| 计算数据 | 本地电脑 | 服务器 | 外置硬盘 |
| 文献 PDF | 本地电脑 | Zotero 云端 | 坚果云 WebDAV |

:::tip 最小成本方案
- 代码：Git + GitHub（免费）
- 笔记和论文：坚果云免费版
- 本地备份：买一块 1 TB 外置硬盘（约 300 元）
- 总成本约 300 元，保护所有重要数据
:::

### 备份验证

:::caution 未经验证的备份不是备份
定期检查你的备份是否真的可用：

1. 每月从备份恢复一个文件，确认内容正确
2. 检查外置硬盘是否正常工作
3. 确认云端同步是否是最新状态
4. 测试在新设备上从 Git 仓库克隆并运行代码
:::

## 常见问题

**Q: 我只用 Git 够不够？**
A: Git 只管理代码（文本文件），不适合管理大数据、论文 PDF、笔记等。你需要 Git + 云同步 + 本地备份的组合。

**Q: 坚果云免费版够用吗？**
A: 对于笔记和小型文件同步，免费版基本够用（每月 1 GB 上传、3 GB 下载）。如果需要同步大量 PDF，建议付费或使用 OneDrive。

**Q: NAS 有必要买吗？**
A: 如果你有大量计算数据（几十 GB 以上），NAS 是个好投资。否则一块外置硬盘就足够了。

**Q: 如何处理服务器上的数据备份？**
A: 大多数研究机构的服务器有自己的备份策略。但不要完全依赖——重要结果务必在本地保留一份副本。

## 小结

- **数据丢失是真实风险**，不要存在侥幸心理
- **同步不等于备份**——同步解决多设备访问，备份解决数据安全
- 不同类型的数据使用不同的管理工具：代码用 Git，笔记用云同步，文献用 Zotero
- **不要同步**虚拟环境、node_modules、.git 目录和大型数据文件
- 遵循 **3-2-1 备份原则**：3 份副本、2 种介质、1 份异地
- 定期验证备份的可用性

## 练习

1. 审查你当前的文件组织方式，参考本章推荐结构进行重组
2. 检查你的云同步目录，排除不应该同步的文件（虚拟环境、缓存等）
3. 设置一个本地备份方案（Time Machine / rsync / 文件历史记录）
4. 确认你的所有代码仓库都有远程备份（`git remote -v`）
5. 列出你的"不能丢失"的数据清单，检查每一项是否满足 3-2-1 原则
6. 从备份中恢复一个文件，验证备份是否有效
