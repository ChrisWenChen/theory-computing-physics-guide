# 第 1 章：计算机与操作系统基础

> 了解你的工具，才能更好地使用它。

## 本章目标

学完本章后，你应该能：

- 描述计算机的基本组成：处理器、内存、存储、输入/输出
- 解释 CPU 和 GPU 的区别，以及各自在科研计算中的角色
- 区分内存（RAM）和硬盘（Disk）的功能差异
- 理解操作系统的作用
- 正确使用文件路径、理解扩展名的含义
- 区分进程、线程和程序
- 理解"编程"到底在做什么

## 动机

你可能觉得"我又不是学计算机的，为什么要了解硬件？"原因很简单：

- 你的模拟程序跑得慢，是 CPU 不够快还是内存不够大？
- 导师说"申请 GPU 节点"，你需要知道 GPU 能加速什么样的计算
- 程序报错 `MemoryError`，你得知道这里的 memory 指的是什么
- 你的数据文件有 50 GB，你需要判断应该存在哪里

理解硬件基础不需要很深入，但**建立正确的心智模型**会让你在遇到问题时知道往哪个方向排查。

## 1.1 计算机的基本结构

一台计算机可以简化为四个部分：

```
  输入设备          处理器 (CPU)          输出设备
  (键盘、鼠标)  →   + 内存 (RAM)     →   (显示器、文件)
                      ↕
                   存储 (硬盘/SSD)
```

| 组件 | 类比 | 作用 |
|------|------|------|
| CPU | 大脑 | 执行计算指令 |
| 内存 (RAM) | 书桌 | 存放正在使用的数据，速度快但断电即失 |
| 硬盘 (Disk/SSD) | 书柜 | 长期存储数据，速度较慢但断电不丢失 |
| 输入设备 | 眼睛和耳朵 | 接收外部信息 |
| 输出设备 | 嘴和手 | 将结果展示给用户 |

:::tip 科研场景中的理解
当你运行一个 Python 脚本时：
1. 脚本文件存储在**硬盘**上
2. Python 解释器将脚本加载到**内存**中
3. **CPU** 逐行执行指令
4. 计算结果输出到屏幕或写回**硬盘**
:::

## 1.2 CPU 与 GPU：它们分别擅长什么

### CPU (Central Processing Unit)

- 核心数较少（通常 4-16 核），但每个核心很强大
- 擅长**顺序执行**复杂的逻辑任务
- 适合：通用计算、逻辑判断多的程序、大部分科研代码

### GPU (Graphics Processing Unit)

- 核心数极多（数千个），但每个核心较简单
- 擅长**大规模并行**计算——同时对大量数据做相同的运算
- 适合：矩阵运算、深度学习、分子动力学模拟、蒙特卡洛模拟

```
CPU: 几个很强的工人，适合做复杂精细的工作
GPU: 几千个普通工人，适合做大量重复的简单工作
```

### 对物理学生意味着什么？

| 任务类型 | 适合的处理器 | 例子 |
|----------|-------------|------|
| 符号计算 | CPU | Mathematica 推导、SymPy |
| 小规模数值计算 | CPU | 求解微分方程、拟合数据 |
| 大规模矩阵运算 | GPU | 密度泛函理论 (DFT)、深度学习 |
| 蒙特卡洛模拟 | CPU 或 GPU | 取决于具体实现 |
| 分子动力学 | GPU | LAMMPS, GROMACS 的 GPU 版本 |

:::info 不必现在就纠结 GPU
大部分入门级科研计算用 CPU 就够了。等你确实需要 GPU 加速时，再深入学习也不迟。
:::

## 1.3 内存与硬盘：容量、速度与用途

这是新手最容易混淆的概念之一。

| 特性 | 内存 (RAM) | 硬盘 (Disk/SSD) |
|------|-----------|-----------------|
| 速度 | 非常快 (~ns 级) | 较慢 (~ms 级，SSD 快很多) |
| 容量 | 较小 (8-64 GB 常见) | 较大 (256 GB - 几 TB) |
| 断电后 | 数据丢失 | 数据保留 |
| 用途 | 存放正在运行的程序和数据 | 存放文件、程序安装包 |
| 价格 | 贵 | 便宜 |

### 科研中的实际影响

**内存不够时会怎样？**

```python
# 这个数组需要约 8 GB 内存
import numpy as np
a = np.zeros((10**5, 10**4))  # 10^9 个 float64
```

如果你的电脑只有 8 GB 内存，运行上面的代码很可能导致程序被系统杀掉（`Killed`）或报 `MemoryError`。

**硬盘空间不够时会怎样？**

- 无法保存新文件
- 程序无法写出结果
- 系统运行变慢甚至崩溃

:::caution 养成习惯：运行大型计算前先估算资源需求
- 数据量有多大？内存够不够？
- 输出文件会有多大？硬盘空间够不够？
- 需要跑多久？CPU 够不够？
:::

## 1.4 操作系统是什么

**操作系统 (Operating System, OS)** 是管理计算机硬件和软件资源的系统软件。它是你和硬件之间的"翻译官"。

```
  你（用户）
     ↓
  应用程序 (Python, VS Code, 浏览器...)
     ↓
  操作系统 (macOS / Linux / Windows)
     ↓
  硬件 (CPU, 内存, 硬盘, 显卡...)
```

### 三大操作系统

| 操作系统 | 内核 | 特点 | 科研使用场景 |
|----------|------|------|-------------|
| macOS | Darwin (类 Unix) | 图形界面好，自带终端 | 个人开发，日常科研 |
| Linux (Ubuntu) | Linux | 开源免费，服务器标准 | 服务器、超算、重度计算 |
| Windows | NT | 用户最多，生态丰富 | 日常使用，通过 WSL 做科研 |

### 为什么科研大多用 Linux？

- 几乎所有超算和计算集群都运行 Linux
- 大量科学计算软件优先支持 Linux
- 命令行工具链最完善
- 开源免费，学校服务器无需付费授权

这不意味着你必须在个人电脑上装 Linux。macOS 天然类 Unix，Windows 通过 WSL 也能获得 Linux 环境。

## 1.5 文件、目录、路径与扩展名

### 文件和目录

- **文件 (File)**：存储数据的基本单位，例如 `simulation.py`、`data.csv`
- **目录 (Directory)**：也叫"文件夹"，用于组织文件

### 路径 (Path)

路径是文件在文件系统中的"地址"。

```bash
# Unix/macOS/Linux 风格（用正斜杠 /）
/home/student/research/simulation.py

# Windows 风格（用反斜杠 \）
C:\Users\student\research\simulation.py
```

**绝对路径 vs 相对路径：**

```bash
# 绝对路径：从根目录开始的完整路径
/home/student/research/simulation.py

# 相对路径：相对于当前目录的路径
# 假设当前在 /home/student/
research/simulation.py    # 相对路径
./research/simulation.py  # 同上，./ 表示当前目录
../other_project/data.csv # .. 表示上一级目录
```

### 扩展名 (Extension)

文件名最后一个 `.` 后面的部分叫扩展名，它**暗示**文件的类型：

| 扩展名 | 类型 | 常见用途 |
|--------|------|----------|
| `.py` | Python 脚本 | 数据分析、模拟 |
| `.f90` | Fortran 源码 | 数值计算 |
| `.c` / `.cpp` | C/C++ 源码 | 高性能计算 |
| `.tex` | LaTeX 文件 | 论文写作 |
| `.csv` | 逗号分隔数据 | 实验数据 |
| `.dat` / `.txt` | 文本数据 | 模拟输出 |
| `.pdf` | PDF 文档 | 论文、报告 |
| `.sh` | Shell 脚本 | 自动化任务 |

:::caution 扩展名不决定文件内容
把 `.txt` 改成 `.py` 不会让一个文本文件变成 Python 程序。扩展名只是一个"标签"，真正决定文件性质的是文件内容。
:::

## 1.6 进程、线程与程序

| 概念 | 类比 | 说明 |
|------|------|------|
| **程序 (Program)** | 菜谱 | 存储在硬盘上的代码/指令，是静态的 |
| **进程 (Process)** | 正在做菜的过程 | 程序被加载到内存中执行，是动态的 |
| **线程 (Thread)** | 做菜时的不同步骤 | 一个进程内可以有多个线程并行执行 |

```bash
# 查看当前运行的进程
# macOS / Linux:
ps aux

# Windows PowerShell:
Get-Process
```

### 为什么这很重要？

- 你的程序跑得很慢，可能是因为只用了**单个线程**，而你的 CPU 有 8 个核心
- 你想同时运行多个模拟，需要理解进程的概念
- 程序"卡死"时，你需要知道如何找到并终止对应的进程

```bash
# 终止进程（Linux/macOS）
kill <进程ID>

# 强制终止
kill -9 <进程ID>
```

## 1.7 什么是编程

**编程 = 用计算机能理解的语言描述解决问题的步骤。**

一个简单的例子——计算谐振子的能量：

```python
# 量子谐振子能级
# E_n = hbar * omega * (n + 1/2)

hbar = 1.0545718e-34   # 约化普朗克常数 (J·s)
omega = 2 * 3.14159 * 1e12  # 角频率 (rad/s)

for n in range(5):
    E = hbar * omega * (n + 0.5)
    print(f"n = {n}, E = {E:.4e} J")
```

你不需要成为"程序员"。对物理学生来说，编程是**工具**，就像数学一样。你需要掌握到能解决自己的物理问题的程度。

### 科研常用编程语言

| 语言 | 特点 | 物理中的用途 |
|------|------|-------------|
| Python | 易学，库丰富 | 数据分析、可视化、快速原型 |
| C/C++ | 高性能 | 大规模模拟、底层库 |
| Fortran | 数值计算传统强项 | 老牌物理代码、超算程序 |
| Julia | 现代高性能 | 新兴科研语言，兼顾易用和速度 |
| Mathematica | 符号计算 | 解析推导、特殊函数 |

## 1.8 科研中的"代码""脚本""软件""环境"分别指什么

这些词在日常交流中经常混用，但它们有不同的含义：

| 术语 | 含义 | 例子 |
|------|------|------|
| **代码 (Code)** | 用编程语言写的文本 | `energy = 0.5 * k * x**2` |
| **脚本 (Script)** | 可以直接运行的代码文件 | `plot_spectrum.py` |
| **软件/程序 (Software)** | 完整的可执行应用 | VASP, Gaussian, LAMMPS |
| **库/包 (Library/Package)** | 别人写好供你调用的代码集合 | NumPy, SciPy, TensorFlow |
| **环境 (Environment)** | 运行代码所需的所有依赖组合 | Python 3.11 + NumPy 1.24 + ... |
| **工具链 (Toolchain)** | 完成某类任务所需的一组工具 | 编译器 + 链接器 + 调试器 |

:::info "环境"是科研计算中最容易出问题的地方
"在我电脑上能跑"是科研计算中最常见（也最令人头疼）的一句话。学会管理环境是本教程的核心目标之一。
:::

## 常见问题

**Q：我需要买很贵的电脑吗？**

A：入门阶段不需要。大部分学习和小规模计算用普通笔记本就够了。大规模计算应该在学校的服务器或超算上进行。建议至少 8 GB 内存和 256 GB SSD。

**Q：M 系列 Mac 适合做科研计算吗？**

A：非常适合。M 系列芯片性能强劲，能效比高。

**Q：我需要学多少硬件知识？**

A：本章的内容就足够了。你需要的只是一些基本的概念，不是深入的硬件工程知识。可以遇到问题再学习。

## 小结

- 计算机由 CPU、内存、硬盘和 I/O 设备组成
- CPU 擅长复杂顺序任务，GPU 擅长大规模并行任务
- 内存是临时快速存储，硬盘是永久慢速存储
- 操作系统是你和硬件之间的桥梁，科研服务器几乎都用 Linux
- 理解文件路径（绝对/相对）是使用命令行的前提
- 程序是静态代码，进程是运行中的程序
- 编程对物理学生来说是工具，不是目的

### 练习 1.1：查看你的电脑配置

在终端（或系统设置）中找到以下信息：

```bash
# macOS
sysctl -n machdep.cpu.brand_string   # CPU 型号
sysctl -n hw.memsize                  # 内存大小（字节）
df -h                                  # 硬盘空间
sw_vers                                # 系统版本

# Ubuntu
lscpu                                 # CPU 信息
free -h                               # 内存信息
df -h                                  # 硬盘空间
lsb_release -a                        # 系统版本

# Windows PowerShell
Get-WmiObject -Class Win32_Processor  # CPU 信息
Get-WmiObject -Class Win32_PhysicalMemory | Select Capacity  # 内存
Get-PSDrive C                         # C 盘空间
winver                                 # 系统版本
```

### 练习 1.2：估算内存需求

一个物理模拟需要存储一个 1000 x 1000 x 1000 的三维数组，每个元素是 64 位浮点数（8 字节）。请计算：

1. 这个数组需要多少内存？（单位：GB）
2. 你的电脑内存够用吗？
3. 如果不够，有什么解决办法？

<details>
<summary>参考答案</summary>

1. 1000 × 1000 × 1000 × 8 字节 = 8 × 10⁹ 字节 = 8 GB（严格来说是 8,000,000,000 字节 ≈ 7.45 GiB）
2. 取决于你的电脑。如果你的电脑有 8 GB 内存，那么仅这一个数组就几乎占满了全部内存（操作系统本身也需要 2-3 GB），实际上不够用。16 GB 或以上才比较充裕。
3. 解决办法包括：
   - 使用更节省内存的数据类型（如 32 位浮点数 `float32`，内存减半为 ~3.7 GiB）
   - 分块处理数据，不要一次性加载整个数组
   - 使用稀疏矩阵（如果数据中有大量零元素）
   - 在内存更大的服务器或 HPC 集群上运行
   - 使用内存映射文件（memory-mapped file），让操作系统按需加载

</details>

### 练习 1.4：CPU 核心与并行

你的 CPU 有多少个核心？如果你要同时运行 4 个独立的蒙特卡洛模拟，每个模拟是单线程的，你的 CPU 能否同时处理它们？为什么？

<details>
<summary>参考答案</summary>

查看 CPU 核心数：

```bash
# macOS
sysctl -n hw.ncpu

# Linux
nproc

# Windows PowerShell
(Get-WmiObject -Class Win32_Processor).NumberOfLogicalProcessors
```

- 如果你的 CPU 有 **4 个或更多核心**（现代笔记本通常有 4-16 核），那么可以同时运行 4 个单线程模拟，每个模拟独占一个核心，互不干扰。
- 如果你的 CPU 只有 **2 个核心**，操作系统仍然可以"同时"运行 4 个模拟（通过时间片轮转调度），但实际上每个模拟只能分到约 50% 的 CPU 时间，总耗时大约是 4 核情况的 2 倍。
- **超线程（Hyper-Threading）**：例如 4 核 8 线程的 CPU 有 4 个物理核心和 8 个逻辑核心。4 个单线程任务可以完全并行运行在 4 个物理核心上，性能接近理想情况。

</details>
