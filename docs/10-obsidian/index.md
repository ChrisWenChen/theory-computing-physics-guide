# 第 10 章：知识管理：Obsidian 与卡片笔记

**Knowledge Management with Obsidian and Zettelkasten**

---

## 本章目标

读完本章后，你应该能够：

- 理解为什么科研需要系统的知识管理
- 使用 Obsidian 创建和管理笔记
- 运用双向链接和标签构建知识网络
- 设计适合科研新手的 vault 目录结构
- 将 Obsidian 与 Markdown、Zotero 结合使用

---

## 动机

科研过程中，你会积累大量的信息：读过的论文、推导过的公式、尝试过的代码方案、导师的建议、会议上的灵感。如果没有一个系统来**捕捉、组织和检索**这些信息，它们很快就会丢失。

Obsidian 是一个基于 Markdown 文件的本地知识管理工具，特别适合科研工作者。

---

## 10.1 为什么科研不仅是写代码

:::caution 常见误区
很多理论/计算物理的学生认为科研 = 写代码 + 跑程序。实际上，科研还包括：
- **阅读和理解**大量文献
- **推导和验证**理论公式
- **记录和反思**实验（计算）过程
- **整理和表达**研究成果
- **讨论和协作**与导师和同学交流
:::

这些活动产生的知识如果不记录，就会被遗忘。一个好的笔记系统不是"锦上添花"，而是**科研基础设施**。

---

## 10.2 笔记系统的作用

一个好的笔记系统应该具备：

| 功能 | 说明 |
|------|------|
| **快速捕捉** | 任何时候有想法都能立刻记下来 |
| **结构化组织** | 笔记之间有清晰的关联 |
| **高效检索** | 三个月后还能找到那个推导 |
| **渐进式整理** | 从草稿到成熟想法的演化 |
| **长期积累** | 读博五年的笔记都能查到 |

### 为什么不用 Word / 记事本 / 微信收藏？

- Word：文件散落各处，无法建立关联
- 记事本：无格式，无法嵌入公式和图片
- 微信收藏：无法编辑和组织，搜索困难
- Notion：优秀但数据在云端，依赖网络，隐私风险

## 10.3 Obsidian 的核心概念

### 什么是 Obsidian？

Obsidian 是一个**本地优先**的 Markdown 笔记工具。所有笔记保存为 `.md` 文件，存在你自己的硬盘上。

### 安装

```bash
# macOS
brew install --cask obsidian

# Windows
winget install Obsidian.Obsidian

# Linux（从官网下载 .deb 安装包）
# 访问 https://obsidian.md/download 下载 .deb
sudo dpkg -i obsidian_*.deb
sudo apt install -f    # 自动补全缺少的依赖
```

### 核心概念

| 概念 | 说明 |
|------|------|
| **Vault** | 一个文件夹，包含所有笔记的根目录 |
| **Note** | 一个 `.md` 文件 |
| **Link** | `[[另一个笔记]]` 形式的双向链接 |
| **Tag** | `#标签` 形式的分类标记 |
| **Graph View** | 笔记之间关系的可视化图谱 |

### 创建你的第一个 Vault

1. 打开 Obsidian
2. 选择 "Create new vault"
3. 给 vault 起个名字（如 `research-notes`）
4. 选择存放位置（建议放在同步盘或 Git 仓库中）

## 10.4 双向链接、标签、图谱

### 双向链接

Obsidian 最核心的功能是**双向链接**。在任意笔记中输入 `[[`，就可以链接到另一个笔记：

```markdown
# Ising 模型笔记

Ising 模型是研究[[相变]]的经典模型。

可以用 [[Metropolis 算法]] 进行模拟。

相关论文：[[Onsager 1944]]

代码实现见 [[ising-mc-code]]
```

当你在"相变"笔记中查看时，会自动显示所有链接到它的笔记（**反向链接**）。

:::tip 双向链接的价值
传统文件夹是**树状结构**，一个文件只能放在一个位置。双向链接让笔记形成**网状结构**，一个概念可以自然地与多个主题关联。这更接近大脑的工作方式。
:::

### 标签

标签用于快速分类和筛选：

```markdown
#论文笔记 #统计力学 #蒙特卡洛 #待整理
```

### 标签 vs 链接

| | 标签 | 链接 |
|--|------|------|
| 形式 | `#topic` | `[[笔记名]]` |
| 用途 | 分类、状态标记 | 概念关联 |
| 示例 | `#待读` `#重要` | `[[Metropolis 算法]]` |
| 建议 | 用于元信息 | 用于知识关联 |

### 图谱视图

打开 Graph View（快捷键 `Ctrl/Cmd + G`），可以看到所有笔记的关系网络。节点是笔记，连线是链接。这有助于发现意想不到的知识关联。

## 10.5 卡片笔记法

卡片笔记法（Zettelkasten）是德国社会学家 Niklas Luhmann 发明的知识管理方法。核心原则：

### 基本原则

1. **原子性**：每张卡片只记一个想法/概念
2. **用自己的话写**：不是复制粘贴，而是理解后重新表达
3. **建立连接**：每张新卡片至少链接到一张已有卡片
4. **渐进发展**：想法通过卡片的积累和重组逐渐成熟

### 笔记类型

| 类型 | 说明 | 示例 |
|------|------|------|
| **闪念笔记** | 临时想法，待整理 | "如果用变分法来处理这个问题会怎样？" |
| **文献笔记** | 读论文的笔记 | Onsager 1944 的关键结论和方法 |
| **永久笔记** | 经过整理的知识卡片 | 关于 Metropolis 算法的完整理解 |
| **项目笔记** | 特定项目的记录 | 毕业论文第三章的计算记录 |

## 10.6 如何记论文、代码、想法、公式

### 论文阅读笔记模板

```markdown
# [[Paper-AuthorYear]] 论文标题

## 元信息
- **作者**：Author et al.
- **年份**：2023
- **期刊**：Physical Review Letters
- **DOI**：10.1103/xxx
- **Zotero 链接**：zotero://select/items/@AuthorYear

## 一句话总结
用变分蒙特卡洛方法计算了二维 Hubbard 模型的基态能量。

## 核心问题
这篇论文要解决什么问题？

## 关键方法
- 使用了 [[变分蒙特卡洛]] 方法
- 试探波函数采用 [[Jastrow 因子]] 形式

## 主要结果
- 基态能量与 [[DMRG]] 结果一致（误差 < 1%）
- 发现了在 $U/t = 8$ 附近的[[相变]]

## 我的思考
- 他们的试探波函数是否可以推广到三维？
- 与 [[我的项目-Hubbard]] 的关联：可以借鉴他们的参数化方式

## 标签
#论文笔记 #蒙特卡洛 #Hubbard模型 #2023
```

### 公式推导笔记

```markdown
# [[derivation-topic]] 推导主题

## 目标
推导二维 Ising 模型的 Onsager 精确解中的临界温度。

## 推导过程
从配分函数出发：
$$
Z = \sum_{\{s\}} e^{-\beta H}
$$

关键步骤（用自己的话）：
1. 转移矩阵方法 → [[转移矩阵]]
2. ...

## 最终结果
$$
\frac{k_B T_c}{J} = \frac{2}{\ln(1 + \sqrt{2})} \approx 2.269
$$

## 参考
- Onsager, Phys. Rev. 65, 117 (1944)
- 参考书 [[Kardar-Statistical-Physics]] 第 7 章

## 标签
#推导 #Ising模型 #精确解
```

## 10.7 适合卢曼卡片笔记法的 Obsidian 目录结构

卢曼（Luhmann）的卡片笔记法将笔记分为几种不同类型，每种类型有不同的生命周期和用途。以下目录结构完全围绕这一方法设计：

│

│   ├── 2024-03-15-想法.md
│   ├── 2024-03-16-灵感.md
│   └── ...
│
├── 1-Literature/             ← 文献笔记（Literature Notes）
│   ├── Onsager1944.md
│   ├── Metropolis1953.md
│   ├── Anderson1958.md
│   └── ...
│
├── 2-Permanent/              ← 永久笔记（Permanent Notes）
│   ├── Monte-Carlo-方法.md
│   ├── Metropolis-算法.md
│   ├── 相变与临界现象.md
│   ├── Ising-模型.md
│   ├── 转移矩阵方法.md
│   └── ...
│
├── 3-Project/                ← 项目笔记（Project Notes）
│   ├── thesis/
│   │   ├── chapter1-notes.md
│   │   ├── chapter2-notes.md
│   │   └── progress-log.md
│   ├── course-computational-physics/

│
├── 4-Reference/              ← 参考资料（Reference）

│   ├── 2023-course-project/

├── daily/                    ← 日志（可选）

### 各类笔记的定义与用法

#### 闪念笔记（0-Fleeting）

**临时的、未经加工的想法。** 随时随地记录，不用在意格式。闪念笔记是"入口"，不是"终点"。

```markdown
# 2024-03-15 想法

- 如果用变分法来处理 Hubbard 模型的基态会怎样？
- 今天组会上老师提到 DMRG 可以处理一维系统，查一下
- Python 的 scipy.sparse 好像可以存稀疏矩阵，试试

#fleeting
```

:::caution 关键习惯
闪念笔记**必须定期清理**（建议每周一次）。每条闪念笔记要么：
- 发展为一条永久笔记或文献笔记
- 合并到已有的永久笔记中
- 确认无价值后删除

如果 `0-Fleeting` 文件夹越来越大，说明清理频率不够。
:::

#### 文献笔记（1-Literature）

**读论文时的笔记。** 记录论文的核心内容，但必须**用自己的话重新表达**，不是复制摘要。

```markdown
# Metropolis1953

## 元信息
- **标题**：Equation of State Calculations by Fast Computing Machines
- **作者**：Metropolis, Rosenbluth, Rosenbluth, Teller, Teller
- **年份**：1953
- **期刊**：Journal of Chemical Physics

## 核心贡献
提出了一种通用的蒙特卡洛采样方法：通过构造满足细致平衡的
马尔可夫链，在任意概率分布中采样。

## 关键思想
接受概率 $\min(1, e^{-\beta \Delta E})$ 保证了马尔可夫链
收敛到玻尔兹曼分布。→ 联系 [[Metropolis-算法]]

## 我的理解
这本质上是用随机游走来探索相空间。接受概率的设计是精妙之处——
它允许"上坡"（能量增加），但概率随能量差指数衰减。

#literature #蒙特卡洛 #1953
```

#### 永久笔记（2-Permanent）

**经过思考和整理的知识卡片。** 这是整个系统中最有价值的部分。每张永久笔记：

- **只讲一个概念**（原子性）
- **用自己的话写**，不是复制教科书
- **包含与其他笔记的链接**

```markdown
# Metropolis 算法

Metropolis 算法是一种 [[蒙特卡洛]] 方法，用于在给定概率分布
中生成样本。它是 [[马尔可夫链蒙特卡洛]]（MCMC）方法的基础。

## 核心步骤
1. 从当前状态 $x$ 提议一个新状态 $x'$
2. 计算能量差 $\Delta E = E(x') - E(x)$
3. 以概率 $A = \min(1, e^{-\beta \Delta E})$ 接受新状态

## 为什么有效
接受概率满足 [[细致平衡]] 条件，保证马尔可夫链的平稳分布
是目标分布（如 [[玻尔兹曼分布]]）。

## 应用
- [[Ising-模型]] 的热力学模拟
- 蛋白质折叠
- 优化问题（[[模拟退火]]）

## 来源
- 原始论文：[[Metropolis1953]]
- 教材参考：[[Kardar-Statistical-Physics]] 第 7 章

#permanent #蒙特卡洛 #算法
```

#### 参考资料（4-Reference）

**工具性的速查笔记。** 不属于知识性的永久笔记，而是实用的备忘录。

```markdown
# NumPy 常用操作速查

## 数组创建
- `np.zeros((m, n))`
- `np.linspace(0, 1, 100)`
- `np.random.rand(m, n)`

## 线性代数
- `np.linalg.eig(A)` — 特征值分解
- `np.linalg.solve(A, b)` — 解线性方程组

#reference #python #numpy
```

#### 归档（5-Archive）

**已完成项目的笔记。** 不删除，但移出活跃区域，避免干扰日常工作。

- 结课的课程项目
- 已发表论文的草稿笔记
- 过时的想法或不再追踪的方向

### 笔记流转：从闪念到永久

```
闪念笔记 ──→ 值得深入？──→ 发展为永久笔记
   │                         ↑
   │                    文献笔记 ──→ 提炼核心概念 ──→ 永久笔记
   │
   └──→ 没有价值 ──→ 删除
```

核心原则：**闪念笔记是临时的，永久笔记是积累的。** 闪念笔记越少越好（说明你在及时整理），永久笔记越多越好（说明你在积累知识）。

:::tip 目录结构原则
- 文件夹是**粗粒度**的分类，不要嵌套太深
- **细粒度**的组织靠双向链接和标签完成
- `0-Fleeting` 是所有新想法的入口，**每周清理一次**
- 不必一开始就设计完美结构，随着笔记积累逐步调整
- 已完成的项目及时移入 `5-Archive`，保持活跃区域整洁
:::

### 推荐插件

| 插件 | 功能 |
|------|------|
| **Templater** | 高级模板功能，自动填充日期、标题等 |
| **Dataview** | 用类 SQL 语法查询和汇总笔记 |
| **Calendar** | 日历视图，方便写日志 |
| **Excalidraw** | 在笔记中画手绘风格的示意图 |
| **Git** | 在 Obsidian 内进行 Git 版本控制 |

:::caution 插件建议
不要一开始就安装太多插件。先用原生功能写一个月笔记，感受到真正的需求后再装插件。插件过多会分散注意力、降低性能。
:::

## 常见问题

:::info FAQ

**Q: Obsidian 和 Notion 选哪个？**
A: Obsidian 是本地优先，数据完全在你手上，Markdown 文件通用。Notion 是云优先，协作方便但数据在服务器上。科研笔记推荐 Obsidian——你的笔记应该能陪你十年以上。

**Q: 笔记太多了怎么找？**
A: 善用搜索（`Ctrl/Cmd + Shift + F`）、双向链接的反向引用、标签筛选。好的链接习惯比好的文件夹结构更重要。

**Q: 每天要花多少时间整理笔记？**
A: 不需要每天整理。建议每周花 30 分钟处理 inbox，将临时笔记分类或添加链接。"完美整理"是陷阱，"够用就好"是原则。

**Q: 可以和同学共享 Obsidian vault 吗？**
A: 可以通过 Git 共享，但 Obsidian 不是协作工具。多人实时编辑请用 HackMD、Google Docs 或 Overleaf。

**Q: 手机上可以用 Obsidian 吗？**
A: 可以。Obsidian 有 iOS 和 Android 版。同步可以用 iCloud（iOS）、Obsidian Sync（付费）或通过 Git。
:::

## 小结

- 科研需要系统的知识管理，不仅仅是写代码
- Obsidian 是基于本地 Markdown 文件的知识管理工具
- **双向链接**是 Obsidian 的核心——用 `[[]]` 连接相关概念
- **卡片笔记法**：每张笔记一个想法，用自己的话写，建立连接
- 按卢曼卡片笔记法组织 vault：闪念笔记→文献笔记→永久笔记
- 定期清理闪念笔记，持续积累永久笔记

## 练习

1. **安装**：下载并安装 Obsidian，创建一个名为 `research-notes` 的 vault
2. **结构**：按照本章建议创建目录结构
3. **论文笔记**：用模板写一篇你最近读过的论文的笔记，包含至少 3 个双向链接
4. **概念笔记**：为你研究领域的 3 个核心概念各写一张卡片笔记，互相链接
5. **日志**：尝试写一周的科研日志，记录每天做了什么、遇到什么问题
6. **整理**：一周后回顾你的 inbox，将临时笔记整理到合适的文件夹
