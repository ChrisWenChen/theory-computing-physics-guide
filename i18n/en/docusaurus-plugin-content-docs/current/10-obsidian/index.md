# Chapter 10: Knowledge Management: Obsidian and Zettelkasten

**Knowledge Management with Obsidian and Zettelkasten**

---

## Chapter Goals

After reading this chapter, you should be able to:

- Understand why research requires systematic knowledge management
- Use Obsidian to create and manage notes
- Build a knowledge network using bidirectional links and tags
- Design a vault directory structure suitable for research beginners
- Integrate Obsidian with Markdown, Zotero, and other tools

---

## Motivation

During the course of research, you accumulate vast amounts of information: papers you have read, formulas you have derived, code approaches you have tried, advice from your advisor, ideas from seminars. Without a system to **capture, organize, and retrieve** this information, it will quickly be lost.

Obsidian is a local knowledge management tool based on Markdown files, particularly well-suited for researchers.

---

## 10.1 Why Research Is More Than Just Writing Code

:::caution Common Misconception
Many theoretical/computational physics students think research = writing code + running programs. In reality, research also includes:
- **Reading and understanding** a large body of literature
- **Deriving and verifying** theoretical formulas
- **Recording and reflecting** on experimental (computational) processes
- **Organizing and presenting** research results
- **Discussing and collaborating** with advisors and peers
:::

The knowledge generated by these activities will be forgotten if not recorded. A good note-taking system is not a "nice-to-have" — it is **research infrastructure**.

---

## 10.2 The Role of a Note-Taking System

A good note-taking system should provide:

| Function | Description |
|----------|-------------|
| **Quick capture** | Jot down any idea the moment it occurs |
| **Structured organization** | Clear relationships between notes |
| **Efficient retrieval** | Find that derivation three months later |
| **Progressive refinement** | Evolve from rough drafts to mature ideas |
| **Long-term accumulation** | Notes from all five years of a PhD remain searchable |

### Why Not Word / Notepad / WeChat Favorites?

- Word: Files scattered everywhere, no way to establish connections
- Notepad: No formatting, cannot embed formulas or images
- WeChat Favorites: Cannot edit or organize, difficult to search
- Notion: Excellent but data lives in the cloud, depends on network, privacy concerns

## 10.3 Core Concepts of Obsidian

### What Is Obsidian?

Obsidian is a **local-first** Markdown note-taking tool. All notes are saved as `.md` files stored on your own hard drive.

### Installation

```bash
# macOS
brew install --cask obsidian

# Windows
winget install Obsidian.Obsidian

# Linux (download the .deb package from the official site)
# Visit https://obsidian.md/download and download the .deb
sudo dpkg -i obsidian_*.deb
sudo apt install -f    # install any missing dependencies
```

### Core Concepts

| Concept | Description |
|---------|-------------|
| **Vault** | A folder that serves as the root directory for all notes |
| **Note** | A single `.md` file |
| **Link** | A bidirectional link in the form `[[Another Note]]` |
| **Tag** | A classification marker in the form `#tag` |
| **Graph View** | A visual graph of relationships between notes |

### Creating Your First Vault

1. Open Obsidian
2. Select "Create new vault"
3. Name your vault (e.g., `research-notes`)
4. Choose a storage location (recommended: a synced folder or Git repository)

## 10.4 Bidirectional Links, Tags, and Graph View

### Bidirectional Links

Obsidian's most essential feature is **bidirectional linking**. Type `[[` in any note to link to another note:

```markdown
# Ising Model Notes

The Ising model is a classical model for studying [[Phase Transitions]].

It can be simulated using the [[Metropolis Algorithm]].

Related paper: [[Onsager 1944]]

Code implementation: see [[ising-mc-code]]
```

When you view the "Phase Transitions" note, it will automatically show all notes that link to it (**backlinks**).

:::tip The Value of Bidirectional Links
Traditional folders form a **tree structure** — a file can only exist in one location. Bidirectional links create a **network structure** where a concept can naturally connect to multiple topics. This is closer to how the brain works.
:::

### Tags

Tags are used for quick classification and filtering:

```markdown
#paper-notes #statistical-mechanics #monte-carlo #to-organize
```

### Tags vs. Links

| | Tags | Links |
|--|------|-------|
| Form | `#topic` | `[[Note Name]]` |
| Purpose | Classification, status markers | Concept association |
| Examples | `#to-read` `#important` | `[[Metropolis Algorithm]]` |
| Recommendation | Use for metadata | Use for knowledge connections |

### Graph View

Open Graph View (shortcut `Ctrl/Cmd + G`) to see a visual network of all your notes. Nodes represent notes, and edges represent links. This helps you discover unexpected knowledge connections.

## 10.5 The Zettelkasten Method

The Zettelkasten (slip-box) method is a knowledge management approach invented by German sociologist Niklas Luhmann. Core principles:

### Basic Principles

1. **Atomicity**: Each card contains only one idea/concept
2. **Write in your own words**: Do not copy-paste — understand first, then rephrase
3. **Establish connections**: Each new card should link to at least one existing card
4. **Progressive development**: Ideas mature through accumulation and reorganization of cards

### Note Types

| Type | Description | Example |
|------|-------------|---------|
| **Fleeting notes** | Temporary ideas, to be organized | "What if I use the variational method for this problem?" |
| **Literature notes** | Notes from reading papers | Key conclusions and methods from Onsager 1944 |
| **Permanent notes** | Refined knowledge cards | A thorough understanding of the Metropolis algorithm |
| **Project notes** | Records for a specific project | Computation log for Chapter 3 of the thesis |

## 10.6 How to Record Papers, Code, Ideas, and Formulas

### Paper Reading Note Template

```markdown
# [[Paper-AuthorYear]] Paper Title

## Metadata
- **Authors**: Author et al.
- **Year**: 2023
- **Journal**: Physical Review Letters
- **DOI**: 10.1103/xxx
- **Zotero link**: zotero://select/items/@AuthorYear

## One-Sentence Summary
Used variational Monte Carlo to compute the ground-state energy of the 2D Hubbard model.

## Core Question
What problem does this paper aim to solve?

## Key Methods
- Used the [[Variational Monte Carlo]] method
- Trial wave function in [[Jastrow Factor]] form

## Main Results
- Ground-state energy consistent with [[DMRG]] results (error < 1%)
- Discovered a [[Phase Transition]] near $U/t = 8$

## My Thoughts
- Can their trial wave function be generalized to 3D?
- Connection to [[My Project - Hubbard]]: their parameterization approach could be adopted

## Tags
#paper-notes #monte-carlo #hubbard-model #2023
```

### Formula Derivation Note

```markdown
# [[derivation-topic]] Derivation Topic

## Goal
Derive the critical temperature in Onsager's exact solution of the 2D Ising model.

## Derivation Process
Starting from the partition function:
$$
Z = \sum_{\{s\}} e^{-\beta H}
$$

Key steps (in my own words):
1. Transfer matrix method → [[Transfer Matrix]]
2. ...

## Final Result
$$
\frac{k_B T_c}{J} = \frac{2}{\ln(1 + \sqrt{2})} \approx 2.269
$$

## References
- Onsager, Phys. Rev. 65, 117 (1944)
- Textbook [[Kardar-Statistical-Physics]] Chapter 7

## Tags
#derivation #ising-model #exact-solution
```

## 10.7 Obsidian Directory Structure for the Zettelkasten Method

### Note Type Definitions and Usage

#### Fleeting Notes (0-Fleeting)

**Temporary, unprocessed ideas.** Jot them down anytime, anywhere — don't worry about formatting. Fleeting notes are an "entry point," not a "destination."

```markdown
# 2024-03-15 Ideas

- What if I used a variational approach for the Hubbard model ground state?
- Advisor mentioned DMRG can handle 1D systems in today's meeting — look into it
- Python's scipy.sparse might be good for storing sparse matrices — try it

#fleeting
```

:::caution Key Habit
Fleeting notes **must be regularly processed** (weekly recommended). Each fleeting note should either:
- Be developed into a permanent note or literature note
- Be merged into an existing permanent note
- Be deleted once confirmed to have no value

If your `0-Fleeting` folder keeps growing, you're not processing frequently enough.
:::

#### Literature Notes (1-Literature)

**Notes taken while reading papers.** Record the core content, but you must **restate it in your own words** — do not copy the abstract.

```markdown
# Metropolis1953

## Metadata
- **Title**: Equation of State Calculations by Fast Computing Machines
- **Authors**: Metropolis, Rosenbluth, Rosenbluth, Teller, Teller
- **Year**: 1953
- **Journal**: Journal of Chemical Physics

## Core Contribution
Proposed a general Monte Carlo sampling method: by constructing a
Markov chain satisfying detailed balance, one can sample from any
probability distribution.

## Key Idea
The acceptance probability $\min(1, e^{-\beta \Delta E})$ guarantees
that the Markov chain converges to the Boltzmann distribution.
→ Related: [[Metropolis-Algorithm]]

## My Understanding
This is essentially using a random walk to explore phase space.
The acceptance probability design is the clever part — it allows
"uphill" moves (energy increase), but with exponentially decaying
probability.

#literature #monte-carlo #1953
```

#### Permanent Notes (2-Permanent)

**Carefully thought-out knowledge cards.** This is the most valuable part of the entire system. Each permanent note:

- **Covers only one concept** (atomicity)
- **Is written in your own words**, not copied from textbooks
- **Contains links to other notes**

```markdown
# Metropolis Algorithm

The Metropolis algorithm is a [[Monte-Carlo-Methods]] technique used
to generate samples from a given probability distribution. It is the
foundation of [[Markov-Chain-Monte-Carlo]] (MCMC) methods.

## Core Steps
1. From current state $x$, propose a new state $x'$
2. Calculate energy difference $\Delta E = E(x') - E(x)$
3. Accept new state with probability $A = \min(1, e^{-\beta \Delta E})$

## Why It Works
The acceptance probability satisfies the [[detailed-balance]] condition,
guaranteeing the Markov chain's stationary distribution is the target
distribution (e.g., [[Boltzmann-distribution]]).

## Applications
- Thermodynamic simulation of the [[Ising-Model]]
- Protein folding
- Optimization problems ([[simulated-annealing]])

## Sources
- Original paper: [[Metropolis1953]]
- Textbook: [[Kardar-Statistical-Physics]] Chapter 7

#permanent #monte-carlo #algorithm
```

#### Reference Materials (4-Reference)

**Practical cheatsheet notes.** Not knowledge-oriented permanent notes, but utility reference material.

```markdown
# NumPy Cheatsheet

## Array Creation
- `np.zeros((m, n))`
- `np.linspace(0, 1, 100)`
- `np.random.rand(m, n)`

## Linear Algebra
- `np.linalg.eig(A)` — eigenvalue decomposition
- `np.linalg.solve(A, b)` — solve linear systems

#reference #python #numpy
```

#### Archive (5-Archive)

**Notes from completed projects.** Not deleted, but moved out of the active area to avoid clutter.

- Finished course projects
- Draft notes for published papers
- Outdated ideas or abandoned directions

### Note Flow: From Fleeting to Permanent

```
Fleeting Note ──→ Worth developing? ──→ Develop into Permanent Note
   │                                      ↑
   │                    Literature Note ──→ Extract core concepts ──→ Permanent Note
   │
   └──→ No value ──→ Delete
```

Core principle: **Fleeting notes are temporary; permanent notes are cumulative.** Fewer fleeting notes is better (it means you're processing them), and more permanent notes is better (it means you're accumulating knowledge).

:::tip Directory Structure Principles
- Folders provide **coarse-grained** classification — do not nest too deeply
- **Fine-grained** organization is handled by bidirectional links and tags
- `0-Fleeting` is the entry point for all new ideas — **process weekly**
- You do not need a perfect structure from the start — adjust as your notes grow
- Move completed projects to `5-Archive` promptly to keep the active area clean
:::

## FAQ

:::info FAQ

**Q: Should I choose Obsidian or Notion?**
A: Obsidian is local-first — your data is entirely in your hands, and Markdown files are universally portable. Notion is cloud-first — convenient for collaboration but your data lives on their servers. For research notes, Obsidian is recommended — your notes should last more than ten years.

**Q: What if I have too many notes to find anything?**
A: Make good use of search (`Ctrl/Cmd + Shift + F`), backlinks from bidirectional links, and tag filtering. Good linking habits matter more than a good folder structure.

**Q: How much time should I spend organizing notes each day?**
A: You do not need to organize every day. Spend about 30 minutes per week processing the inbox — categorize temporary notes or add links. "Perfect organization" is a trap; "good enough" is the principle.

**Q: Can I share an Obsidian vault with classmates?**
A: You can share via Git, but Obsidian is not a collaboration tool. For real-time multi-person editing, use HackMD, Google Docs, or Overleaf.

**Q: Can I use Obsidian on my phone?**
A: Yes. Obsidian has iOS and Android apps. Sync options include iCloud (iOS), Obsidian Sync (paid), or Git.
:::

## Summary

- Research requires systematic knowledge management — it is about more than writing code
- Obsidian is a knowledge management tool based on local Markdown files
- **Bidirectional links** are Obsidian's core feature — use `[[]]` to connect related concepts
- **Zettelkasten method**: One idea per note, write in your own words, establish connections
- Organize your vault using the Zettelkasten method: Fleeting → Literature → Permanent notes
- Regularly process fleeting notes and continuously accumulate permanent notes
